```text
init. Set up the design context for this project. Frontend only — React + Vite. There is no backend yet: every screen must run on realistic mock data behind a thin service layer (e.g. /src/services/*.ts returning Promises), so it can be swapped for a real API later.

## Product
[APP NAME] is an AI-powered pedagogical platform for teachers. Teachers organize exams by class, upload exams and graded answer sheets, and a set of AI agents:
- adapts exam questions for neurodivergent students (color blindness, ADHD, autism/ASD, dyslexia, dyscalculia),
- builds a pedagogical profile for each student (competencies, a 1–100 performance score, and whether a gap looks technical or related to neurodivergence),
- generates diagnostic assessments tailored to each student's profile.
The core of the product is a data dashboard: a heatmap of class performance by subject subtopic (e.g. law of sines, law of cosines), where the teacher can drill into any student's profile.

## Users
Primary: school and university teachers. They're busy, not always tech-savvy, and use it on laptops/desktops (secondary: tablets). They need to understand a class at a glance and trust the AI's output without feeling replaced by it. The teacher always reviews and approves what the AI produces.
Indirect: students, including neurodivergent ones. Their data is sensitive, so the tone has to be respectful, never labeling or clinical.

## Brand personality
Calm, intelligent, warm, trustworthy. Think "a sharp, kind teaching assistant", not "a surveillance analytics tool". Confident but quiet. The AI is present but not loud: no gimmicky robot imagery, no sparkle overload.

## Aesthetic direction
- Very modern, soft, and airy. The UI should feel light and fluid, like everything glides.
- Generous whitespace, soft radii, subtle layered surfaces (gentle elevation and very soft shadows, light translucency where it helps), restrained borders.
- A calm, mostly neutral base with one confident accent color plus a carefully designed data palette.
- Typography: a clean, contemporary sans with good numerals (tabular figures for data). Clear hierarchy, nothing cramped.
- Light theme first; design tokens should make a dark theme possible.
- Anti-references: generic admin templates, dense enterprise BI dashboards, purple-gradient "AI startup" clichés, heavy glassmorphism, cartoonish edtech.

## Motion principles (important)
The app must FEEL fluid. Motion is part of the identity, not decoration:
- Spring-based, short, interruptible animations (suggested: Motion for React / framer-motion).
- Shared-layout transitions between related views (e.g. heatmap cell → student profile).
- Smooth sidebar expand/collapse, staggered list/grid entrances, soft hover/press feedback, skeleton → content crossfades, animated number counters on KPIs.
- Nothing slow or bouncy for its own sake: most UI motion is 150–300ms, and no layout jank.
- Fully respect prefers-reduced-motion, plus an in-app "reduce motion" toggle. Accessibility is part of the product mission here.

## Accessibility (non-negotiable, it's the product's purpose)
- WCAG AA contrast minimum.
- Heatmap and all charts must be color-blind safe (perceptually uniform sequential palette, plus value labels/patterns on demand; never color alone).
- Full keyboard navigation, visible focus states, semantic HTML, ARIA where needed.
- Dyslexia-friendly reading options (comfortable line length/spacing; optional font switch).

## Technical constraints
- React + Vite + TypeScript, React Router.
- Design tokens (color, type scale, spacing, radius, shadow, motion durations/easings) defined once and used everywhere.
- Component-driven: reusable primitives (Button, Card, Badge, Tooltip, Dialog, Tabs, Table, EmptyState, Skeleton).
- UI language: Brazilian Portuguese (pt-BR).
```
